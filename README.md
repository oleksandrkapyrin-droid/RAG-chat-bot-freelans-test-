
# RAG-чатбот на базі внутрішніх документів

Невеликий RAG-застосунок: відповідає на питання, спираючись лише на завантажені документи компанії (PDF), і вказує джерело (файл + номер фрагмента) для кожної відповіді.

## Стек
- Python 3.13
- Groq API (модель `openai/gpt-oss-20b`) — безкоштовний рівень, виклик через `requests`
- ChromaDB — локальна векторна база (зберігається в папці `chroma_db/`)
- `sentence-transformers` (`paraphrase-multilingual-MiniLM-L12-v2`) — модель embeddings, працює локально, підтримує українську
- FastAPI + Uvicorn — простий API

## Встановлення

1. Створити віртуальне середовище та активувати його:

py -3.13 -m venv .venv
.venv\Scripts\Activate.ps1

2. Встановити залежності:

python -m pip install -r requirements.txt

3. Створити файл `.env` у корені проєкту з вмістом:

GROQ_API_KEY=твій_ключ

   Ключ безкоштовний, отримати можна на console.groq.com.

## Підготовка документів

1. Покласти PDF-файли в папку `docs/`.
2. Проіндексувати їх (розбиває на фрагменти, рахує вектори, записує в `chroma_db/`):

python index.py

   Команду треба повторити щоразу, коли документи в `docs/` змінюються. Перший запуск довший: завантажується модель embeddings.

## Запуск API

uvicorn api:app --reload


Сервер підніметься на `http://127.0.0.1:8000`. Інтерактивна документація з можливістю тестувати запити: `http://127.0.0.1:8000/docs`.

### Приклад запиту

POST /ask
Content-Type: application/json

{
“question”: "Що таке Python?"
}


Відповідь:
```json
{
  "answer": "...",
  "sources": ["Файл: ..., Чанк: ...", "Файл: ..., Чанк: ..."]
}
```

Якщо запит до LLM завершився помилкою (наприклад, вичерпано ліміт Groq), API повертає код `502` з поясненням у полі `detail`.

## Структура проєкту

- `app.py` — запит до Groq API та системний промпт
- `db.py` — підключення до ChromaDB та модель embeddings
- `index.py` — читання PDF, розбиття на фрагменти, запис у базу
- `rag.py` — пошук релевантних фрагментів і формування відповіді
- `api.py` — FastAPI-застосунок з ендпоінтом `POST /ask`
- `docs/` — вхідні PDF-документи (не входять у репозиторій)
- `chroma_db/` — локальна векторна база (не входить у репозиторій, створюється `index.py`)

## Відомі обмеження

- Groq безкоштовний рівень має ліміти на кількість запитів, при перевищенні повертається код `502`.
- Документи наразі обробляються локально й повністю, тексти документів передаються в Groq API при кожному запиті для формування відповіді — для конфіденційних даних варто уточнити політику Groq щодо обробки запитів.
- Якість пошуку залежить від довжини та способу розбиття документів на фрагменти; для дуже довгих чи складно структурованих документів може знадобитись тонке налаштування розміру фрагмента.
